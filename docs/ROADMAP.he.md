## שלב 3
### מודול AI (שירות נפרד, `ai-worker`)
עקרונות:
- **הסכמה נפרדת** להעברת וידאו או מידע אישי לשירות AI חיצוני, ברמת העסק וגם ברמת העבודה. ברירת המחדל: כבוי.
- **כל פלט מוצג כהמלצה** עם רמת ודאות. "אושר ע"י טכנאי" הוא שדה נפרד, ואין עדכון אוטומטי של סטטוס או חיוב.
- עיבוד בתור אסינכרוני (Postgres `jobs` queue או Redis) כדי לא להעמיס על השידור.

ארכיטקטורה מתוכננת:
```
media (וידאו) → ai-worker → FFmpeg: חילוץ פריים כל N שניות + תמלול אודיו (אופציונלי)
                         → מודל חזותי/שפה (API חיצוני או מקומי) → טבלת ai_findings
                           {job_id, kind: timeline|summary|anomaly|idle, t_start, t_end, text, confidence, model, created_at, accepted_by}
```
יכולות: ציר זמן של שלבי התיקון, טיוטת סיכום עבודה, זיהוי זמנים ללא פעילות, דוח שירות ל-PDF, ועוזר לטכנאי (חיפוש בהיסטוריה ובמאגר ידע והצעת בדיקות).

### נוספים
- מצלמות IP: ‏RTSP pull דרך MediaMTX, ‏ONVIF discovery, ‏PTZ דרך ONVIF (רק כשזה מאומת מול המצלמה)
- תשתית SaaS: הרשמה עצמית, ניהול מנויים, חיובים (סליקה), התראות מכסה במייל
- אינטגרציית S.Y CRM: מפתחות API, ‏webhooks חתומים ומזהים חיצוניים (ראו [API.md](API.md))
- אפליקציית מובייל, רק אם יתברר שהדפדפן אינו מספיק
